# 测试报告解析规则

## 1. 文件格式

### 文件命名
```
2026-05-12_vcp1.txt
2026-05-13_vcp1_vcp2_plb.txt
```

### 日期提取
- 从**文件名**提取：`2026-05-12` → `2026-05-12`
- 正则：`(\d{4})-(\d{2})-(\d{2})`

### 线体提取
- 从**文件名**提取：包含 vcp1/vcp2/plb（不区分大小写）
- 多线体用下划线分隔
- 存储时转换为逗号分隔：`VCP1, VCP2, PLB`

---

## 2. 字段格式规则

### 2.1 核心原则
- **单一条目**：字段名和内容写在**同一行**，不使用圈号
- **多条目**：字段名单独一行，下方缩进用 `① ② ③` 列出

### 2.2 单一条目字段（同行）
```
【日期】2026-05-14
【工单】M126041900006，共3528 PCS
【测试总时长】6小时（09:30-12:00, 14:30-18:00）
【待办项】无
【明日计划】
测试场景：VCP1/VCP2线放板机全流程（测试环境）
需要协调事项：无
```

### 2.3 多条目字段（缩进圈号）
```
【今日计划】
	① 垂直电镀VCP1自动化测试（放板机）
	② VCP1线PDA配方下发

【实际场景】
	① 自动化测试：VCP1（测试环境）
	② PDA配方下发：VCP1/VCP2/PLB（正式环境）

【流程】
	① 自动化：叫料→AGV送料...
	② PDA：手持lot+设备编码

【测试结果】
	① VCP1自动化测试：卡在AGV 🛑
	② PDA配方下发：成功 ✅

【今日计划实际是否完成】
	① VCP1自动化测试：尚未完成 ❌
	② PDA配方下发：已完成 ✅
```

### 2.4 字段列表

| 字段 | 条目数 | 格式 |
|------|--------|------|
| 【日期】 | 单一 | 同行 |
| 【今日计划】 | 多条 | 单独行 + 缩进圈号 |
| 【测试总时长】 | 单一 | 同行，格式：`X小时（HH:MM, HH:MM-HH:MM）` |
| 【实际场景】 | 多条 | 单独行 + 缩进圈号 |
| 【工单】 | 单一 | 同行，格式：`【工单】工单号，共xxx PCS` |
| 【流程】 | 多条 | 单独行 + 缩进圈号 |
| 【问题汇总】 | 特殊 | 见第3章 |
| 【待办项】 | 单一 | 同行，无则写"无" |
| 【测试结果】 | 多条 | 单独行 + 缩进圈号 |
| 【今日计划实际是否完成】 | 多条 | 单独行 + 缩进圈号 |
| 【明日计划】 | 复合 | `测试场景：`、`明细流程：`、`需要协调事项：` |

## 3. 【问题汇总】格式规则

### 3.1 子模块格式

| 情况 | 格式 | 示例 |
|------|------|------|
| 无问题 | `模块名：无` | `投收板机：无` |
| 单个问题 | `模块名：问题描述 (状态)` | `主线设备：vcp2线设备没有自动切换在线模式 (待厂商确认) 🔁` |
| 多个问题 | 模块名单独一行，下方缩进用圈号 | 见下方 |

### 3.2 多问题示例
```
【问题汇总】
	投收板机：
		① 退空载时，倒车入点位的位置不对 (待调整) 🔁
		② 退空载回去的路线不对 (待排查) 🔁
	自动化物流（海康）：小车经常与平台失联 (待处理) ⚠️
	主线设备：无
	软件集成（SIE）：
		① VCP2线PDA配方下发失败 (已修复) ✅
		② 工作流放板机载具编码未写入 (待验证) ⚠️
```

### 3.3 子模块列表
| 模块名 | 说明 |
|--------|------|
| 投收板机 | 投收板机设备问题 |
| 自动化物流（海康） | 海康自动化物流问题 |
| 主线设备 | 主线设备问题 |
| 软件集成（SIE） | SIE软件集成问题 |

## 4. 问题状态判断

### 4.1 状态关键词

| 状态 | 关键词 | 图标 |
|------|--------|------|
| **已解决** | `已解决`、`已完成`、`已修复` | ✅ |
| **排查中** | `排查`、`正在排查` | 🔍 |
| **待处理** | `待`、`尚未`、`未完成`、`未测试`、`占用`、`阻塞` | ⚠️ 🔁 ❌ 🛑 |

### 4.2 判断逻辑
```
if 包含 "已解决" or "已完成" or "已修复" or "✅":
    → 已解决
elif 包含 "排查" or "🔍":
    → 排查中
elif 包含 "待" or "尚未" or "未完成" or "未测试" or "占用" or "阻塞" or "⚠️" or "🔁" or "❌" or "🛑":
    → 待处理
else:
    → 待处理（默认）
```

## 6. 【明日计划】格式

### 格式
```
【明日计划】
测试场景：VCP1/VCP2线放板机全流程（测试环境）
明细流程：
	① 放板机：叫料→AGV送料→安全交互→配方下发→放板请求→TrackIn→退空载→AGV取空载→送线边仓
	② 收板机：叫空载→AGV安全交互→接收批次配方信息→TrackOut→退满载→AGV取满载→送满载入库
	③ PDA配方下发
需要协调事项：需要IT帮忙做工艺跳站
```

### 说明
- `测试场景：` 单一条目，同行
- `明细流程：` **多条目**，字段单独行 + 缩进圈号
- `需要协调事项：` 单一条目，同行

---

## 7. 统计口径

| 指标 | 计算方式 |
|------|----------|
| 问题总数 | 问题列表中所有条目（不含"无"） |
| 已解决 | 状态="已解决"的数量 |
| 待处理 | 状态="待处理"的数量 |
| 排查中 | 状态="排查中"的数量 |
| 未解决问题 | 待处理 + 排查中 |
| 线体问题数 | 按线体分组统计各状态数量 |

---

## 8. 关键词库

### 状态关键词
```
已解决: 已解决, 已完成, 已修复, ✅
排查中: 排查, 正在排查, 🔍
待处理: 待, 尚未, 未完成, 未测试, 占用, 阻塞, ⚠️, 🔁, ❌, 🛑
```

### 线体关键词
```
VCP1: VCP1, vcp1
VCP2: VCP2, vcp2
PLB: PLB, plb
```

### 特殊处理
- `生产暂停` → 不是问题状态，是客观描述
- `甲方经理验收` → 不是问题，是中断原因
- `设备在生产` → 不是问题，是暂停原因
